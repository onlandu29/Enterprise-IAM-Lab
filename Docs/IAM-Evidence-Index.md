# IAM Operational Evidence Index

## Purpose

This document maps each IAM control implemented in the lab to the evidence generated by that control.

The objective is to demonstrate how IAM controls produce reviewable evidence that can support security operations, governance, compliance, and audit activities.

## Notable Control Scenario

Employee `1003` provides an end-to-end exception scenario.

The employee's role is `Finance_Accountant`, but the current security group is `GG-Marketing-Users` instead of the expected `GG-Finance-Accountants`.

The lab detects this mismatch during reconciliation.

The remediation process identifies:

- Remove `GG-Marketing-Users`
- Add `GG-Finance-Accountants`

The exception is then represented in the IAM exception register and access certification evidence.

This demonstrates how an IAM control can move from:

**Detection → Evidence → Exception → Remediation → Certification**

## Audit and Governance Value

The evidence artifacts demonstrate several enterprise IAM practices:

### Traceability

IAM actions produce records that can be reviewed after execution.

### Accountability

Access requests contain approval and decision information.

### Preventive Controls

SoD and privileged-access controls can block inappropriate access before provisioning.

### Detective Controls

Reconciliation and certification identify access that requires investigation.

### Corrective Controls

Remediation evidence documents how access discrepancies should be corrected.

### Continuous Monitoring

Metrics and control-health reporting provide a consolidated view of IAM control performance.

## Scope

This evidence framework is implemented using simulated CSV data and PowerShell-generated reports.

It is designed to demonstrate IAM governance concepts without connecting to or modifying production identity systems.
